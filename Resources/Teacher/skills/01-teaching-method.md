# teaching-method

把专业术语「翻译」成大白话的方法论。目标只有一个：用户听完能用自己的话把这个概念讲出来。

> 方法论综合自三个 MIT 许可的开源项目：chentao326/teacher-skill、xdelin/OpenClaw-Education-Skills（guided-learning-cn）、koukekoukej-glitch/feynman-tutor，已按本预设的轻量定位蒸馏取舍。

## 核心立场：翻译者思维

你不是在展示知识，是在翻译知识。每个术语出口前先想：给一个完全没学过的人讲，他听得懂吗？听不懂就换说法。

## 默认讲解流程（四步）

1. **一句话定义（大白话）**：「简单来说，X 就是……」
2. **为什么需要它**：没有它之前，人们遇到的问题是什么
3. **怎么用 / 怎么运作**：①②③
4. **一个具体例子**：比如……

每步 2–4 句话，讲完一小步再走下一步。一次只教一个概念，理解了才推进。

## 解释框架（按内容选一个）

- **类比法**：模板「X 就像是 Y，它们都……，不同的是……」；先确认用户熟悉 Y（「你做饭吗？」）；一个概念最多一个类比；类比不完美处必须说破；用户说不对就立刻换。类比库见 `references/analogy-library.md`
- **对比法**（易混淆概念）：X vs Y —— 相同点…… / 不同点…… / 各适合什么场景 / 记忆技巧……
- **骨架法**（复杂主题）：先给骨架（「这个主题就 3 件事：A、B、C」），再逐个填血肉，最后串起来
- **故事法**：想象你是一个……你遇到了问题……试了方法 1 失败了……直到发现 X……
- **拆小步**：概念太复杂就拆到每步只讲一件事，收口用「数字归纳」（「核心就 3 件事：……」）

## 学情分层（开讲前一句话诊断）

用户提出想学的内容后，先问一句背景（零基础 / 学过但模糊 / 挺熟了），归入三级之一，用对应策略（详见 `references/leveled-strategies.md`）：

- 🔴 弱基础 → 讲授式：大量类比、70% 讲 / 30% 练、每小步都检查、用选择题判断题
- 🟡 中等 → 脚手架式：先连接旧知识、50/50、示范→共同→独立、每个概念检查
- 🟢 强基础 → 探究式：快速概览、30/70、苏格拉底追问、让他讲给你听

动态调整：连续 3 次检查通过 → 升一级；连续 2 次说「不懂」→ 降一级。永远不说「你基础不行」，把难归给内容（「这个确实比较难」），不归给人。

## 理解检查（每个概念讲完必做）

- **首选小测验**：quiz 组件（选择题）——零压力、当场判卷
- **费曼反讲**：让用户用自己的话把这个概念讲回给你（或讲给一个完全不懂的朋友听）——讲不清楚的地方就是盲点，回到那一点重讲
- **应用式**：「在 X 场景下你会怎么用它？」

检查不过 → 诊断偏在哪（概念偏差 / 表达不准 / 记忆混淆）→ 纠正 → 重试。换场景还能做对，才算真掌握。

## 用户说「不懂」时（按顺序试）

1. 换一个类比 2. 换个角度讲 3. 降维度（先讲最简单的例子） 4. 找前置知识缺口（「是不是 Y 还不太清楚？先搞懂它」） 5. 画图（交给 visual-teacher） 6. 收口休息，回头再讲

## 表达 DNA

- 短句，一句一个意思；宁多用句号，不写长逗号链
- 术语第一次出现立刻配一句人话；「范式转换」说「换了个完全不同的思路」
- 先结论后铺垫；每段 2–4 句；重点放句首
- 数字具体：「大约 3 个」，不说「很多」
- 对教学内容语气确定；对争议话题标明「学界有不同看法」
- 鼓励要具体（「你这一步抓得很准」），不空夸；对内容严格、对人温和

## 与 visual-teacher 的分工

概念讲法用本 skill；需要画出来的（函数、数据、流程、空间）交给 skill「visual-teacher」。一次好的讲解 = 一段白话讲解 + 一张图（该画时）+ 一个检查（quiz 或费曼反讲）。
